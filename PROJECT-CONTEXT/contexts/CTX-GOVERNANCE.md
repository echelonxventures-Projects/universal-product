## Mandatory rules (global, critical)

- **CST-AUTHORIZED-SIDE-EFFECTS** External side effects need authorization: No commit, push, merge, release, deployment, billing change or other external write without the owner's authorization for that action.
- **CST-CONFIG-OVER-CODE** Configuration over code: Features, providers, vocabularies and runtime backends are entity/config data, never code branches; features ship OFF by default and are enabled by writing configuration.
- **CST-EVIDENCE-BEFORE-CLAIMS** No claim without observed evidence: Never report a test as passed, a feature as implemented or a state as verified unless the command ran or the inspection happened and its result was observed and recorded; a plan, prompt or generated file is not an implementation.
- **CST-EXPLAINABILITY** Law 005 — Explainability: Every artifact must answer what happened, who authorized it, which policy allowed it, what evidence supports it, and with what confidence.
- **CST-FROZEN-PRIMITIVES** 27 frozen primitives: The 27 primitives in _registry/primitives.json are frozen; none may be added without constitutional amendment and proof of mathematical unavoidability.
- **CST-KNOWLEDGE-ONCE** Law 002 — Knowledge Once: Every artifact id, primitive and canonical term is defined exactly once; every concept has one canonical owner, and everything else references or derives from it.
- **CST-NO-DESTRUCTIVE-CLEANUP** No loss of unique knowledge: Unique requirements, decisions, constraints, rationale, evidence and unresolved issues are never deleted or summarised away; retirement is a lifecycle transition with approval, and consolidation must map every unique item to its destination.
- **CST-NO-PRIVATE-ARCHIVES-IN-GIT** Private conversation archives stay out of git: Private conversation exports and attachments are archived only in access-controlled storage (CONTEXT_ARCHIVE_DIR); the repository holds their manifest metadata, never their bytes; CI uses synthetic fixtures.
- **CST-NO-SECRETS** No credentials in the repository or in derived context: Secrets (.env, keys, the keyring, the registry key) are never committed, and never copied into context packs, logs, reports or handoffs.
- **CST-NODE-ENGINE** Node ≥ 22.13: The runtime requires Node 22.13 or newer (built-in node:sqlite); CI runs 22.13, 22 and 24.
- **CST-PRESERVE-WORKING-TREE** Preserve the owner's working tree: Never reset, clean or overwrite uncommitted user changes to make work easier; record them in the baseline and work around them.
- **CST-PROJECTION-LAW** Law 003 — Projection Law: Documents are generated from the registry, never authored; editing a projected document directly is a constitutional violation — change the registry and re-project.
- **CST-SEAL-DERIVED** The compiled registry seal is derived, never committed: _registry/canonical.json and canonical.lxr are compiled deterministically from the corpora and registry JSON and are not committed; data/registry.json and data/master.json are per-deployment secrets.
- **CST-SUPERSEDED-NOT-AUTHORITY** Superseded originals are provenance, not truth: Files in _superseded/ (and any record in lifecycle superseded or historical-evidence) are preserved provenance and must never be used as current authority.
- **CST-ZERO-HARDCODING** Law 001 — Zero Hard Coding: No product, service, offer, contract, currency, country, language, industry or marketplace concept may appear as a schema type; they are runtime projections of configuration.

## Decisions in force

### DEC-REGISTRY-AS-SOT — The registry (_registry/*.json) is the single source of truth and every constitutional document is a projection generated from it.
- Status: **approved** · Authority: repository constitution as committed (UCOS-REPOSITORY-INDEX.md); approver and date not recorded · Decided: unrecorded
- Context: Hand-authoring 93 artifacts would define the same concept many times and drift on each retelling.
- Selected: Truth lives in _registry/*.json; node _registry/project.js projects the documents; node _registry/audit.js enforces the laws.
- Rationale: Hand-authoring would violate Law 002 (Knowledge Once); projection makes Law 003 executable.
- Rejected: hand-author the 93 documents (violates Law 002 — the same concept defined 93 times, drifting on each retelling)
- Affects: CST-PROJECTION-LAW, CST-KNOWLEDGE-ONCE · Sources: SRC-REPOSITORY-INDEX#S0002

### DEC-SEALED-CANONICAL-COMPILE — The corpora and registry JSON compile into one sealed canonical registry (lib/canonical.js) that the runtime reads; the seal is derived and reproducible, never stored.
- Status: **approved** · Authority: recorded in commit 7daf85b and the session-19 memory entry; owner approval not separately recorded · Decided: 2026-10-06
- Context: Declarations were spread across the corpora and registry files with no single runtime source.
- Selected: node _registry/compile.js compiles, gates (five integrity criteria) and seals with AES-256-GCM + HMAC-SHA256 and a per-input sha256 manifest; the artifacts are gitignored.
- Rationale: One compiled, authenticated source makes drift and tampering detectable while keeping the sources as the authority.
- Rejected alternatives: none evidenced
- Affects: CST-SEAL-DERIVED · Sources: SRC-GIT-HISTORY#S0036; SRC-MEMORY-LEDGER#S0033
