## Decisions in force

### DEC-CTX-BYTE-BUDGETS — Budgets are enforced in bytes; token figures are estimates at 3 bytes/token and labelled as estimates.
- Status: **proposed** (newly proposed — no historical approval exists) · Authority: proposed by the implementing agent; awaiting owner approval (TASK-CTX-0002) · Decided: unrecorded
- Context: Packs must fit small context windows, but no tokenizer ships with the repository and token counts are model-specific.
- Selected: Byte budgets (schemas/config.json) with a conservative 3 B/token estimate shown next to them.
- Rationale: Bytes are exact and model-independent; 3 B/token over-estimates tokens for English prose (~4 B/token), erring towards smaller packs.
- Rejected: bundle a tokenizer (adds a dependency and is still model-specific)
- Affects: REQ-CTX-PACKS · Sources: SRC-CONV-2026-10-22-MASTER-PROMPT (§16 Phase 1)

### DEC-CTX-DERIVED-EDGES — Graph edges are derived from record fields through schemas/relations.json; there is no separate edge file.
- Status: **proposed** (newly proposed — no historical approval exists) · Authority: proposed by the implementing agent; awaiting owner approval (TASK-CTX-0002) · Decided: unrecorded
- Context: A dependency written on a record and an edge written elsewhere can disagree.
- Selected: Each relation declares which record fields emit it; the graph is rebuilt from the records on every run.
- Rationale: One fact, one place (Knowledge Once applied to the graph).
- Rejected: a separate edges.json (two places for one fact)
- Affects: REQ-CTX-GRAPH · Sources: SRC-CONV-2026-10-22-MASTER-PROMPT (§16 Phase 1)

### DEC-CTX-DETERMINISTIC-TIME — Generated files carry the knowledge snapshot date (knowledge/state.json asOf), not the wall clock; wall-clock time is recorded only in receipts and handoffs.
- Status: **proposed** (newly proposed — no historical approval exists) · Authority: proposed by the implementing agent; awaiting owner approval (TASK-CTX-0002) · Decided: unrecorded
- Context: Generated outputs are drift-checked byte for byte; a timestamp would make every build differ.
- Selected: generatedAt = state.asOf in packs and views; createdAt = now in receipts/handoffs (events, not projections).
- Rationale: Deterministic outputs make drift a real signal while events keep their true time.
- Rejected: wall-clock generatedAt in packs (every rebuild would differ and drift detection would be meaningless)
- Affects: REQ-CTX-PACKS, REQ-CTX-INVALIDATION · Sources: SRC-CONV-2026-10-22-MASTER-PROMPT (§16 Phase 1)

### DEC-CTX-GIT-AS-ARCHIVE — Repository evidence is archived by git blob id + sha256 in the manifest; private exports go to a write-once content-addressed store outside git.
- Status: **proposed** (newly proposed — no historical approval exists) · Authority: proposed by the implementing agent; awaiting owner approval (TASK-CTX-0002) · Decided: unrecorded
- Context: Original evidence must be preserved by bytes and restorable after the live file changes, without duplicating 2 MB of corpora or committing private data.
- Selected: git-blob / git-history storage kinds for repository evidence; 'store' kind (CONTEXT_ARCHIVE_DIR, default .context-archive/, gitignored) for private material.
- Rationale: Git's object store is already append-only and content-addressed; pinning the blob id makes every captured version restorable with `git cat-file`, so no second copy can drift. Private material never enters a public history.
- Rejected: copy sources into PROJECT-CONTEXT/archives/ (duplicates ~2 MB and creates a second copy that can drift); commit conversation exports (publishes private data (CST-NO-PRIVATE-ARCHIVES-IN-GIT))
- Affects: REQ-CTX-ARCHIVE · Sources: SRC-CONV-2026-10-22-MASTER-PROMPT (§16 Phase 1)

### DEC-CTX-LOCATION — Continuity knowledge lives in PROJECT-CONTEXT/knowledge/*.json; its markdown views and packs are generated; UCOS artifacts are imported read-only from _registry/manifest.json.
- Status: **proposed** (newly proposed — no historical approval exists) · Authority: proposed by the implementing agent; awaiting owner approval (TASK-CTX-0002) · Decided: unrecorded
- Context: The system needs a canonical home for requirements, decisions, sources, tasks and context specs without competing with the constitutional registry.
- Selected: A separate PROJECT-CONTEXT/ tree, using the same projection pattern as _registry/ (authored JSON in, generated documents out).
- Rationale: _registry/ is the UCOS constitutional corpus: its files are inputs to the sealed compile (lib/canonical.js), so adding operational records there would change the seal and mix project-operations knowledge into constitutional content. A separate tree keeps one owner per concept and reuses the repository's proven pattern.
- Rejected: extend _registry/*.json (changes the sealed compile's inputs and mixes operational knowledge into the constitution); free-form markdown memory like .workbuddy-ai/memory/MEMORY.md (not machine-checkable, grows without bound (111 KB), no freshness or traceability)
- Affects: REQ-CTX-NO-COMPETING-SOT, REQ-CTX-KNOWLEDGE-MODEL · Sources: SRC-CONV-2026-10-22-MASTER-PROMPT (§16 Phase 1)

### DEC-CTX-MEMORY-LEDGER-HISTORICAL — The existing .workbuddy-ai/memory/MEMORY.md is left untouched and archived as historical evidence; new continuity is recorded through schema-validated handoffs.
- Status: **proposed** (newly proposed — no historical approval exists) · Authority: proposed by the implementing agent; awaiting owner approval (TASK-CTX-0002) · Decided: unrecorded
- Context: MEMORY.md is a 111 KB narrative ledger of sessions 2026-09-17 → 2026-10-07 and the only surviving record of those sessions.
- Selected: Archive it (SRC-MEMORY-LEDGER), cite its segments, and stop growing it as the continuity mechanism.
- Rationale: Rewriting or compacting it would destroy the only evidence of those sessions; as an unstructured narrative it cannot be checked for freshness or completeness.
- Rejected: compact or rewrite MEMORY.md (destroys unique historical evidence); keep appending to MEMORY.md (unbounded, unverifiable, not machine-readable)
- Affects: REQ-CTX-HANDOFF, REQ-CTX-ARCHIVE · Sources: SRC-CONV-2026-10-22-MASTER-PROMPT (§16 Phase 1)

### DEC-CTX-ZERO-DEPENDENCIES — The continuity system uses only the Node standard library, including a small JSON Schema subset validator that rejects unsupported keywords.
- Status: **proposed** (newly proposed — no historical approval exists) · Authority: proposed by the implementing agent; awaiting owner approval (TASK-CTX-0002) · Decided: unrecorded
- Context: Schema validation and hashing are needed; the platform minimises dependencies.
- Selected: Own validator (lib/context/schema.js) supporting exactly the keywords the schemas use; it throws on any other keyword.
- Rationale: No new install or supply-chain surface; a schema cannot claim a rule the validator silently ignores.
- Rejected: ajv (new dependency for a small, fixed schema surface)
- Affects: REQ-CTX-KNOWLEDGE-MODEL · Sources: SRC-CONV-2026-10-22-MASTER-PROMPT (§16 Phase 1)
