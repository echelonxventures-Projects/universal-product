- Statement: Original source bytes are preserved with sha256, size, provenance, sensitivity, capture/creation/import times and segment boundaries; missing, inaccessible or not-retained sources are recorded as such; originals are never replaced by summaries.

## Decisions in force

### DEC-CTX-GIT-AS-ARCHIVE — Repository evidence is archived by git blob id + sha256 in the manifest; private exports go to a write-once content-addressed store outside git.
- Status: **approved** (newly proposed — no historical approval exists) · Authority: repository owner · Decided: 2026-10-22
- Context: Original evidence must be preserved by bytes and restorable after the live file changes, without duplicating 2 MB of corpora or committing private data.
- Selected: git-blob / git-history storage kinds for repository evidence; 'store' kind (CONTEXT_ARCHIVE_DIR, default .context-archive/, gitignored) for private material.
- Rationale: Git's object store is already append-only and content-addressed; pinning the blob id makes every captured version restorable with `git cat-file`, so no second copy can drift. Private material never enters a public history.
- Rejected: copy sources into PROJECT-CONTEXT/archives/ (duplicates ~2 MB and creates a second copy that can drift); commit conversation exports (publishes private data (CST-NO-PRIVATE-ARCHIVES-IN-GIT))
- Affects: REQ-CTX-ARCHIVE · Sources: SRC-CONV-2026-10-22-MASTER-PROMPT (§16 Phase 1)

### DEC-CTX-MEMORY-LEDGER-HISTORICAL — The existing .workbuddy-ai/memory/MEMORY.md is left untouched and archived as historical evidence; new continuity is recorded through schema-validated handoffs.

## Further issues (lower severity)

- **ISS-GIT-HISTORY-SHALLOW-CAPTURE** [defect, high, resolved] SRC-GIT-HISTORY was captured from a shallow clone with a clone-dependent serializer. RESOLVED. The original git-history capture (commit 4d4e7fe) ran `git rev-list --reverse --format="%H %ad %s" 441d772` in a shallow clone whose only boundary was 3577ace, so it recorded a truncated 61-commit history (7974 B, sha256 87deb12d…). In any full clone the same command walks all 79 ancestors and the checksum can never match, which failed context:verify, restore-check, the generated quality report and 10 context tests. The verifier also downgraded a git-history mismatch to a warning whenever the clone was shallow, hiding the problem. Fixed: the historical record keeps its identity but is marked not-retained (its bytes were never stored); its exact bytes were recovered (sha256 match) as SRC-GIT-HISTORY-LEGACY-RECOVERED; future captures use the canonical, fail-closed ctx-git-history/1 serializer (SRC-GIT-HISTORY-441D772-V1); verify enforces append-only source identity.
