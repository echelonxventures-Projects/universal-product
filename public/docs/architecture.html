1. System Overview

Core Stack

ComponentTechnologyNotes
RuntimeNode.js (≥22.5)Zero external dependencies - uses native HTTP, SQLite, Crypto
DatabaseSQLite / PostgreSQLPrimary: SQLite (single-file); Migration path: PostgreSQL via migrate.js
FrontendVanilla JavaScriptNo frameworks, no CDN dependencies
Multi-Tenant100% Data IsolationEvery store has independent data, cannot cross-access
DeployableSingle NodeDesigned for single-node deployment; no distributed systems required

Key Architectural Principles

Entity-Driven: Every table is a declared entity with fields, types, validation, and permissions. Add new entities via Data Studio — CRUD, forms, and audit appear automatically.
Registry-Driven: All configurations (currencies, calendars, benefits, providers) are data in meta_lists — add a new civilization, planet, or currency with no code changes.
Constitutional Value Exchange: GOIP Ω∞ implements a single 8-stage chain for any incentive, offer, or reward — from coupons to Mars-colony credits.

Domains (67 Total)

Each domain owns exactly one store and has a unique discriminator — this makes overlap impossible by construction. Examples:
  • Incentive Domain: owner=offers, discriminator=every value-exchange row
  • Gift Card Domain: owner=coupons, discriminator=kind='gift_card'
  • Government Benefit Domain: owner=offers, discriminator=funder='government'
  • Membership Domain: owner=goip_entitlements, discriminator=benefit='membership_upgrade'

5. Security Stack (10 Layers)

LayerProtectionImplementation
L1TransportCSP (Content Security Policy), frame-ancestors, nosniff, TLS/HSTS
L2SessionCSRF double-submit (timing-safe), origin-pinned mutations, tenant-pinned state
L3Credentialsscrypt v2 (policy-tunable N/r/p) + pepper, transparent v1→v2 upgrade on login
L4Password Policyplatform-configured length/classes/blocklist + history reuse guard
L5At RestAES-256-GCM envelope seals on gateway secrets, AAD-bound to tenant|provider|field
L6Keysversioned keyring (data/master.json, 0600), rotation API auto-rewraps all seals
L7AuditSHA-256 hash-chained log with verification endpoints (tamper detection)
L8Abusedurable token-bucket rate limits + per-account lockout with exponential backoff
L9Supply Chainsha384 SRI (Subresource Integrity) injected into every served JS/CSS tag; parameterized SQL
L10Isolationtenant-scoped data, platformOnly entity guards, role gates, suspended-store blocks

Audit Chain

Every privileged action is recorded in audit_log:

{
  id: INTEGER PRIMARY KEY AUTOINCREMENT,
  tenant_id: INTEGER,
  actor_type: TEXT NOT NULL DEFAULT 'system',
  actor_id: INTEGER,
  actor_name: TEXT,
  action: TEXT NOT NULL,
  entity: TEXT,
  entity_id: TEXT,
  meta: TEXT DEFAULT '',
  ip: TEXT,
  created_at: TEXT NOT NULL DEFAULT datetime('now'),
  prev_hash: TEXT,    -- hash of previous audit entry
  hash: TEXT           -- SHA-256 of this entry + prev_hash
}

Verification: GET /api/platform/chain/verify[?tenant=]

Entity Engine (Data Studio)

Every table is a declared entity — add new entities via Data Studio:

POST /api/meta/entity-def
{
  "name": "custom_object",
  "fields": [
    {"name": "title", "type": "text", "required": true},
    {"name": "price", "type": "number", "required": false}
  ],
  "permissions": ["view", "create", "update"]
}

Result:
- CRUD forms appear automatically
- Validation rules are enforced
- All operations are audited
- Entity data stored in entity_data table

Database Migration

Platform Console → Runtime → Database

1. Configure PostgreSQL connection string
2. Click "Dry-run" to generate migration plan
3. Review migration SQL
4. Click "Apply" to migrate from SQLite → PostgreSQL
5. Switch driver to postgres

Migration is handled by lib/migrate.js + lib/pg.js (async pool + dialect translator).
