# 2026-09-17

## Code review of the uncommitted Postgres-cutover work

Reviewed the dirty working tree (`lib/db.js`, `lib/enterprise.js`, `lib/migrate.js`, `lib/pg.js`,
`lib/sql.js`, `test/smoke.js` + new `lib/pgbridge.js`, `lib/pgworker.js`). Wrote the report to
`REVIEW.md` at the repo root.

Baseline: `npm test` → 343 passed / 0 failed (README still says 191 — stale).

Three blockers that break at runtime on PG:
- `INSERT OR REPLACE` untranslated (`lib/api.js:588`, translator only handles `OR IGNORE` at `lib/sql.js:48`)
- `INSERT OR IGNORE` → bare `INSERT`, so ignore semantics are lost (`lib/api.js:456,272` + 16 seed sites)
- `MAX(0, x)` is SQLite scalar MAX; PG needs `GREATEST` (`lib/offers.js:213,214,242`)

Also: indexes are never migrated (72 dropped, measured 0 `CREATE INDEX` in `plan()`), `to_char(now(), …)`
is timezone-dependent vs SQLite's UTC `datetime('now')`, `LIKE` becomes case-sensitive, the console
"switch to Postgres" writes runtime config while `USE_PG` reads env only (status lies), and the PG
connection string with password is returned by `GET /api/platform/db` and rendered into the DOM.

Good fixes in the diff: `"t"/"d"` → `"T"/"D"` wire types, `ci32` → `i16` for the Parse param count,
`normalizeConn`, the `interval` operator, `OVERRIDING SYSTEM VALUE` placement, `topoSort`, and `setval`.

Most instructive finding: the hand-rolled fake PG transport encoded the *same* bug as the implementation
(`test/smoke.js:770`), so the test passed while the real protocol was misread. `queryP`, `apply()`, and the
bridge all have zero coverage. Recommended one real-Postgres integration test as the top follow-up.
